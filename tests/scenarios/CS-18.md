## 1. Scenario

A large institutional client executes a **$450 million block trade in a single equity (8% of ADV)**. The trade was **pre-arranged with the block desk**, has **proper documentation**, and is part of a **disclosed portfolio-rebalancing programme**. The **correct system output is NO_ALERT** — after verification. This is the deliberate trap: raw anomaly heuristics (huge notional, 8% of ADV) look suspicious, but the trade is legitimate, and **escalating it costs 25 points**.

## 2. Detection → Verification (two-step, this is the crux)

**Step 1 — TM raises suspicion.** TM's volume/impact monitor sees a $450M single-name print at 8% of ADV and fires a **preliminary** signal, `c = 0.68`. Critically, TM commits its remainder to **ignorance** `m(Θ)`, *not* to "benign" — a surveillance agent raises suspicion, it does **not** assert innocence (per [consensus-algorithm.md §5](../../docs/conflict-resolution/consensus-algorithm.md)).

**Step 2 — verification looks for exculpatory record.** Before any human is paged, the false-positive tree runs a verification: is there an **authenticated pre-arrangement + disclosed mandate**? Here, **yes** — the block-desk pre-arrangement ticket and the disclosed rebalancing programme both authenticate. Only *this explicit, authenticated evidence* may commit **benign mass** `m({B})`.

## 4. Consensus — Dempster–Shafer with benign mass (full rule, K ≠ 0)

Unlike the agreement scenarios (K = 0), here the two sources **disagree** — TM leans violation, verification asserts benign — so the **general Dempster rule with normalization** applies. Frame Θ = {V, B}.

```
TM (raises suspicion, no innocence claim):
    m_TM({V}) = 0.95 · 0.68 = 0.646 ;  m_TM(Θ) = 0.354 ;  m_TM({B}) = 0

Verification (authenticated exculpatory record, source auth 0.90, record conf 0.90):
    m_ver({B}) = 0.90 · 0.90 = 0.81 ;   m_ver(Θ) = 0.19 ;  m_ver({V}) = 0

Conflict:  K = m_TM({V})·m_ver({B}) = 0.646 · 0.81 = 0.52326
Normaliser: 1 − K = 0.47674

m({V}) = [ m_TM({V})·m_ver(Θ) ] / (1−K) = 0.646·0.19 / 0.47674 = 0.1227 / 0.47674 = 0.257
m({B}) = [ m_TM(Θ)·m_ver({B}) ] / (1−K) = 0.354·0.81 / 0.47674 = 0.2867 / 0.47674 = 0.601
m(Θ)   = [ m_TM(Θ)·m_ver(Θ)  ] / (1−K) = 0.354·0.19 / 0.47674 = 0.0673 / 0.47674 = 0.141
                                                        (sum = 0.999 ✓)

Belief(V) = m({V}) = 0.26   Belief(B) = 0.60
```

TM's initial violation belief (0.646) **collapses to 0.26** once authenticated benign mass enters; benign belief (0.60) dominates. `Belief(V) = 0.26 < 0.30` suppression threshold → **NO_ALERT**.

## 5. Escalation — suppression as a *documented* T0 decision

Belief(V) 0.26 → band **T0**; there is **no severity floor** (severity resolves to NO_ALERT); no special trigger. Outcome: **suppress**. But suppression is **not** a silent drop — the system writes a **suppression record**: which pre-arrangement ticket, which disclosed mandate, the authenticating source, the hashes, and the DS computation above. A regulator can later confirm the machine suppressed for a legitimate, recorded reason. If the record had **not** authenticated, no benign mass would be committed and the block would route normally to a human — protecting against silently dropping a real violation.

## 6. Report & audit

RG produces **no violation report**; instead the Audit Ledger stores the signed suppression reasoning, and a **feedback event** (confirmed true-negative) is sent to recalibrate TM's block-trade heuristics. All under `correlation_id = C18-BLOCK`, `audit_classification = OPERATIONAL`.
