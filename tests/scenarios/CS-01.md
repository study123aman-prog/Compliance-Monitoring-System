## 1. Scenario

A portfolio manager accumulates a significant position in Company X over three weeks. Internal email reveals the PM attended a private dinner with Company X's CFO four weeks ago. Company X announces an acquisition two days after the last purchase; the price rises 35%. The System must connect the *trading pattern* (TM's domain) with the *communications linkage* (CS's domain) and escalate to a Director for SAR filing.

## 2. Trigger & ingestion

A batch/streaming re-evaluation on the `transactions` topic flags the accumulation pattern once the post-announcement price move materialises. The triggering transaction event is persisted to the Kafka log **before** processing (persist-before-process invariant), assigned `correlation_id = C1` which will tie the entire case together across agents and time.

## 3. Agent detection

**TM (trading domain, authority `w=0.95`).** Detects abnormal pre-announcement accumulation: position size vs 60-day baseline, timing cluster ending 2 days before a price-moving event, single-name concentration. Calibrated confidence `c_TM = 0.72` (accumulation alone is suggestive, not conclusive). Asserts `severity = HIGH`.

**CS (communications domain, authority `w=0.95`).** On receiving the Orchestrator's `QUERY`, searches captured communications for links between the PM and Company X. Finds the private-dinner email with the CFO four weeks prior. Calibrated confidence `c_CS = 0.80`. This is *linkage evidence* — it supplies the intent/opportunity element that trading data alone cannot.

## 5. Consensus

Both agents assert a violation with no benign mass, so the selection rule chooses **Dempster–Shafer combination** (agreement/corroboration). Each agent is discounted by its authority in the domain of *its own* evidence:

```
m_TM({V}) = 0.95 · 0.72 = 0.684 ;  m_TM(Θ) = 0.316
m_CS({V}) = 0.95 · 0.80 = 0.760 ;  m_CS(Θ) = 0.240      K = 0 (no benign mass)
Belief(V) = 0.684 + 0.760 − 0.684·0.760 = 0.924  ≈ 0.92
s* = max(HIGH, elevated-by-corroboration) = CRITICAL
```

Corroboration across two independent domains lifts a HIGH @ 0.72 into a **CRITICAL @ 0.92**. Deterministic: identical inputs always yield 0.92.

## 6. Escalation

CRITICAL → severity floor **T4**; confidence 0.92 → band **T4**; SAR regulatory clock → special trigger **T4 + 24 h SLA**. Routed to **Director/CCO**. Decision-support package: case summary, severity/confidence + mechanism, evidence bundle (txn refs + dinner-email ref, each hashed), per-agent assessments (TM 0.72 / CS 0.80 with weights), consensus result (masses above), applicable regs (10b-5, FINRA 2010, ITSA), recommended action ("file SAR within 24 h"), SLA clock, similar prior cases. Filing requires **dual T4 sign-off** ([critical-filing tree](../../docs/escalation/decision-trees/critical-filing-tree.md)).

## 7. Report & audit

RG produces (a) a **SAR draft** (regulator profile, full evidence + citations) and (b) a **board risk summary** (risk posture + single recommendation) — same facts, two renderings. Every step (ALERT, QUERY, RESPONSE, consensus computation, ESCALATION, sign-offs, report) is a **hash-chained, ECDSA-signed** entry in the WORM audit ledger under `correlation_id = C1`, so the entire decision is replayable years later (SEC 17a-4(f)).
